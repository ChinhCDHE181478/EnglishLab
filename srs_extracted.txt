80: II. Software Requirement Specification
81: 1. Overall Requirements
82: 1.1 Context Diagram
83: The context diagram illustrates the overall interaction between the EnglishLab system and its main actors, including Learners, Teacher, Content Manager, Training Manager, Manager, and Admin, along with external services such as AI Engine Service, Payment Service, Email Service, and Lark Meeting Service. The system serves as a centralized platform for managing online learning, classroom activities, assessments, learning content, scheduling, and administrative operations. Each role interacts with the system according to its responsibilities to support a complete English learning and classroom management environment.
84: 1.2 Main Workflows
85: 1.2.1 Enroll Online Course Workflow
86: The Course Enrollment and Payment Workflow starts with the Learner browsing available courses and viewing the system-displayed course catalog to see specific course details before attempting to add a selected course to their cart. The system first verifies if the Learner has already registered for this course, displaying a registration confirmation and returning them to the catalog if true, but if false, the Learner views their cart and proceeds to checkout, provided there are registered courses in the cart. During checkout, the system generates a payment request that is sent to the Payment Gateway for processing, and if the initial payment verification fails, the system requests another status check, ultimately displaying an error message and redirecting the Learner back if the payment fails again. However, upon a successful payment verification, the system grants course access, enabling the Learner to access the course, learn the lessons while their progress is tracked, take lesson practices whose results are recorded, and finally complete the course to receive an officially issued completion status.
87: 1.2.2 Take Placement Test Workflow
88: The Placement Exam Workflow details the process of a Learner taking a timed practice test, beginning with the Learner choosing to take the placement exam, which prompts the EnglishLab System to load the necessary exam content. Once the Learner starts the exam, the system simultaneously starts a countdown timer and enters an interruptible activity region where the Learner cycles through viewing a displayed question, answering it, and having the system auto-save the answers until no questions remain, at which point the Learner manually submits the exam. Crucially, if the Learner runs out of time before finishing, a time event is triggered that instantly interrupts the question-answering loop and forces the system to execute an auto-submit action. Regardless of whether the exam was submitted manually by the Learner or automatically due to the timer expiring, the workflow converges as the system calculates the final score, generates a detailed result report, and presents it to the Learner for review before the process concludes.
89: 1.2.3 Enroll Classroom Workflow
90: The Enroll Classroom Workflow initiates when the EnglishLab System creates a class, generates a corresponding class record, assigns a timetable, and assigns a teacher to the course. Following these setup steps, the workflow splits into two parallel tracks where the system simultaneously notifies the Teacher, who then views their assigned class and waits for the session to start, and checks whether the class is full or registration is closed. If the class is still open for registration, the system enrolls the Learner, sends them a notification, and allows them to view both the class information and the timetable, eventually merging this track with the Teacher's track. Once both parties are ready, the parallel tracks synchronize as the Teacher conducts the class session while the Learner joins the learning activities, bringing the entire classroom training process to its completion.
91: 1.2.4 Take Practice & Homework Workflow
92: The Practice and Homework Workflow within the EnglishLab system begins with the Teacher deciding to manage either homework or practice activities. If Homework Management is selected, the Teacher creates and assigns a homework task, allowing the Learner to access and submit their work, which the system stores so the Teacher can review and grade the submission, prompting the system to store the final grades for the Learner to view before the process ends. Alternatively, if Practice Management is chosen, the Teacher creates a practice activity by selecting a format such as 4 Skills, Flashcard, or Quiz, which is then published by the system so the Learner can access learning resources, choose the practice activity, and complete the selected format. Once completed, the system automatically grades the practice using AI, enabling the Teacher to review the results and provide feedback that the Learner can subsequently view to conclude the workflow.

7362: -  For pages with large amounts of data, the system must support multi-criteria search to narrow down results.
7363: - The web interface must be compatible with popular browsers such as Chrome, Firefox, Safari, and Edge.
7364: 2
7365: Software Interfaces
7366: - The system shall interface with a PostgreSQL database management system for secure data storage and retrieval.
7367: - The system will integrate with the PayOS payment gateway to handle online transactions (payment initiation, result processing, and inquiry).
7368: - The system must integrate with an Email Service (SMTP) to send automated notifications like password resets or payment receipts.
7369: 3
7370: Communication Interfaces
7371: - The system will employ secure HTTPS protocols (TLS 1.2 or higher) to ensure encrypted communication between the client and server.
7372: - Data exchange between the Frontend and Backend via RESTful APIs must use the JSON format.
7373: - All API requests must be authenticated using JSON Web Tokens (JWT) to prevent unauthorized access
7374: 4.2 Quality Attributes
7375: No
7376: Category
7377: Requirement
7378: 1
7379: Performance
7380: - UI Response Time: Use testing tools (e.g., Apache JMeter) to ensure that the response time for typical user interactions is under 2 seconds under normal load conditions.
7381: - Concurrency: The system must be capable of handling at least 1,000 concurrent user interactions without degradation in performance or data integrity.
7382: - Payment Processing: The integration with PayOS should ensure that payment status updates are reflected in the system within 5 seconds after receiving the gateway's callback.
7383: 2
7384: Security
7385: - Data Encryption: All sensitive data transmission must be secured using HTTPS protocols with SSL/TLS encryption.
7386: - Password Hashing: User passwords must be securely hashed using a strong algorithm (e.g., BCrypt or SHA-512) before being stored in the database.
7387: - Authentication: The system must use JSON Web Tokens (JWT) for authenticating API requests. Tokens must be validated for every protected resource access to prevent unauthorized entry.
7388: - The system should implement role-based access control (RBAC) for user and admin actions.
7389: 3
7390: Usability
7391: - The system must comply with modern web GUI standards to ensure a short learning curve for new users.
7392: - The system should provide hover tooltips and inline help for complex features or technical terms to assist users without external documentation.
7393: - The workflow for complex tasks, such as creating a course or processing a refund, must be intuitive and follow a logical step-by-step process.
7394: 4
7395: Compatibility
7396: - The system should be compatible with major web browsers (Chrome, Firefox, Safari, Edge) and different devices (laptops, desktops, tablets).
7397: - Responsive design for optimal display on desktops, tablets.
7398: 5
7399: Maintainability
7400: - The code should follow coding standards and best practices to enhance maintainability.
7401: - The system should be well-documented to facilitate future updates and bug fixes.
7402: 5. Requirement Appendix
7403: 5.1 Business Rules
7404: ID
7405: Rule Definition
7406: BR-01
7407: Passwords must be at least 8 characters long and contain uppercase, lowercase, numbers, and special characters.
7408: BR-02
7409: An email address can only be associated with one active account in the system.
7410: BR-03
7411: User accounts are automatically locked after 5 consecutive failed login attempts (applies to standard email/password login).
7412: BR-04
7413: System-generated OTPs for password recovery expire after 5 minutes from the time of request.
7414: BR-05
7415: Learners can only enroll in courses if the course status is "Active", capacity limit is not reached, and they are not already enrolled.
7416: BR-06
7417: The OTP entered by the user must exactly match the system-generated OTP and must not be expired.
7418: BR-07
7419: Uploaded files (for homework or assignments) must not exceed 20MB and must be in PDF, DOCX, JPG, or PNG formats.
7420: BR-08
7421: Quizzes and Placement Exams must auto-submit immediately when the countdown timer reaches zero.
7422: BR-09
7423: Audio recordings for speaking practice must not exceed 5 minutes in length.
7424: BR-10
7425: Learners can only download learning materials that belong to a Teacher-led Classroom.
7426: BR-11
7427: Teachers can only manage attendance, homework, and practice contents for the classrooms they are explicitly assigned to.
7428: BR-12
7429: Class attendance can only be marked or updated on or after the scheduled date of the class session.
7430: BR-13
7431: Audio files uploaded by Teachers for listening practices must be in MP3/WAV format and not exceed 20MB.
7432: BR-14
7433: A syllabus or online course cannot be deleted if it has active enrolled learners or is linked to an active entity.
7434: BR-15
7435: Online Course names and Classroom names must be unique within the system.
7436: BR-16
7437: A teacher cannot be assigned to a classroom if their teaching schedule conflicts with the classroom's timetable.
7438: BR-17
7439: The number of learners assigned to a classroom cannot exceed its maximum capacity.
7440: BR-18
7441: User accounts cannot be permanently deleted from the database to maintain data integrity; they can only be locked or deactivated.
7442: BR-19
7443: A support ticket can only be marked as "Resolved/Closed" after at least one reply has been sent by the admin/manager.
7444: BR-20
7445: A course can appear at most once in a learner's wishlist and at most once in the shopping cart; a course the learner is already enrolled in cannot be added to the wishlist or the cart.
7446: BR-21
7447: Only courses with status "Active"/"Published" and a valid price (including free courses with price = 0) can be added to the cart or purchased at checkout.
7448: BR-22
7449: For paid courses, enrollment is granted only after the payment is successfully confirmed by the PayOS payment gateway; free courses (price = 0) are enrolled immediately without payment.
7450: BR-23
7451: Upon successful checkout, the purchased courses are removed from the learner's cart and a payment receipt is sent to the learner's registered email.
7452: BR-24
7453: Only authorized Content Managers can create, view, update, or delete placement exam content.
7454: BR-25
7455: Each placement exam question must belong to exactly one valid skill section (Listening, Reading, Writing, or Speaking).
7456: BR-26
7457: Objective placement exam questions must have at least two answer options and at least one correct answer.
7458: BR-27
7459: Writing and Speaking placement exam questions must include a clear prompt or task instruction.
7460: BR-28
7461: The score value of a placement exam question must be a positive number greater than zero.
7462: BR-29
7463: Learners must not be able to view the correct answers before or during a placement exam; correct answers are visible only to authorized management users.
7464: BR-30
7465: Viewing placement exam content must not modify any data, and displayed lists must reflect the latest available exam/question data.
7466: BR-31
7467: Placement exam content that has already been used in learner attempts must not be hard-deleted; it must be deactivated instead, and historical learner results must be preserved.
7468: BR-32
7469: Deleting placement exam content requires confirmation; deleted or inactive questions must not appear in new learner attempts, and their related answer key and score configuration must be removed or deactivated.
7470: BR-33
7471: If a create or update operation fails validation, no invalid placement exam data is saved and the previously valid version remains unchanged.
